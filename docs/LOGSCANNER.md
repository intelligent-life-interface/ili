### Log → Kanban-Karte: `bug_fixer.py` (Ollama-Triage + Entscheidungs-Karten, seit 2026-07-11)
Erzeugt aus Server-Logs Bug-Karten auf `home-stack-bugs`. **Triage = Ollama (lokal, gratis)** via `_ollama_classify_and_fix` (CrowAI-Gateway `localhost:8870`, `BUG_FIX_OLLAMA_MODEL` env, Default `gemma2:9b`); liefert `{relevant, severity, ursache, stelle, fix, sicher}`. **Kein automatischer Claude-Call mehr** (User-Entscheid 11.07.26): Ist Ollama **unsicher** (`sicher=false`, auch bei unparsebarer Antwort oder Ollama-Ausfall) oder die **Severity high**, wird die Karte als **⚠️ ENTSCHEIDUNG** angelegt (`owner=me`, Optionen: Claude-Fix anstossen / löschen / beobachten) — gefiltert wird NUR, was Ollama sicher aussortiert. Der alte Claude-Weg (`_classify_and_fix`, CLI-Bridge 8950, Modell `BUG_FIX_MODEL`) bleibt für manuelles Fix-Ausarbeiten. Aufruf: `venv/bin/python bug_fixer.py [--board home-stack-bugs] [--hours 24] [--max 5]`.
- **Keine Dubletten / Status-Check:** Karten-ID ist **deterministisch** aus der Bug-Signatur (`_bug_card_id` = sha1 von Service + normalisierter Headline; Zeitstempel/PIDs/`log_id`-artige Tokens werden rausnormalisiert). Existiert die ID schon auf dem Board (egal welche Spalte: Gemeldet/Triage/In Arbeit/Behoben), wird sie übersprungen (Status geloggt). Zusätzlich semantischer Dedup gegen offene Karten (`dedup_finder.check_duplicate(..., use_ai=False)` = nur Jaccard, **kein Ollama**). **Die Normalisierung muss identisch in `~/.claude/skills/bug-triage/triage.py` bleiben**, sonst matcht die Triage-Status-Anzeige nicht.
- **Kaskaden-Gruppierung (2026-07-11, `_group_cascades`):** Vor dem Karten-Anlegen wird zusammengefasst, was EIN Ereignis ist: (a) identische normalisierte Headline über mehrere Journal-Units — `podman[pid]` spiegelt Container-stdout, derselbe Fehler erschien doppelt (einmal Service `podman`, einmal `zigbee2mqtt-H25`); (b) Folge-Fehler desselben Service innert 60 s (z2m-Crash = 4 Headlines: Error while starting → Failed to start → Check https → Exiting). Repräsentant = echter Unit-Name (nicht `podman`/`conmon`/`systemd`), Folge-Headlines stehen als `🔁`-Block in der Karte. Der Status-Check prüft gegen die IDs ALLER Gruppen-Mitglieder (`alle_ids`), damit eine morgen anders einsteigende Kaskade keine neue Karte anlegt. Messung 11.07.: 64 Log-Errors (48 h) → 13 Ereignisse.
- **Log-Quelle in der Karte:** Beschreibung beginnt mit `📍 Log-Quelle` (systemd journal / Container-Log / Datei inkl. journalctl-/podman-Befehl) + Zeitstempel + Dienst, dann Fehler, Claude-Fix, Log-Kontext.
- **Repo-Regel:** Schreibt **nur** über `BoardRepository.update` (fcntl-Lock). Früher schrieb es `boards/*.json` direkt + nutzte `uuid4` als ID → erzeugte zwingend Dubletten (beides 2026-06-24 behoben).
- **Filter (Noise + Severity):** (1) lokaler Vorfilter `_NOISE_LOCAL` (gratis, spart den Ollama-Call bei offensichtlichem Rauschen: broken pipe, client disconnect, …). (2) **Der EINE Ollama-Call liefert Filter + Fix-Idee + Konfidenz in einem Schritt.** Nicht-relevante und Karten unter `MIN_SEVERITY` (env, Default `med`; CLI `--min-sev`) werden NUR verworfen, wenn `sicher=true` — sonst ⚠️ ENTSCHEIDUNG-Karte. Karten-Label nach Severity (🔴 high `#fc8181` / 🟠 med `#f6ad55` / 🟢 low `#68d391`), Severity steht oben in der Beschreibung, Karten setzen `desc` UND `description`.
- **Autonom:** `bug-fixer.timer` (user) **täglich 03:30 nachts** (bis 11.07.26: 06:30; User-Wunsch: nachts, keine Tages-Token — Triage ist ohnehin Ollama/gratis) → `bug-fixer.service` ruft `bug_fixer.py --hours 24 --max 20 --min-sev med`. Units **ohne `User=`**. Achtung: Ist der Ollama-PC (.122) nachts aus, entstehen ⚠️ ENTSCHEIDUNG-Karten ohne Analyse (kein Bug geht verloren). Manuell: `systemctl --user start bug-fixer.service`.
